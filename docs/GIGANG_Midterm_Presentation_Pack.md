# 🎯 [Part 1] 발표 전략 및 심사위원 공략 포인트

### 1. 심사위원의 마음을 여는 4대 핵심 키워드
* **"이미 실제로 돌아갑니다 (v3.1 완주)"**: 계획 단계가 아니라 실제 단말(Chrome 확장 + Windows Agent), MySQL 8.0 2.4만 건 DB(Tailscale VPN), 클라우드(Railway), 분석 엔진, 대시보드가 실시간 통신 중임을 강조합니다.
* **"딜레마의 해결"**: 사후약방문(SIEM) vs 무차별 차단(DLP)의 한계를 상관분석(Correlation)으로 풀었다는 기술적 명분을 제시합니다.
* **"기업 현실 반영 (프라이버시 & 실효성)"**: 직원 사생활을 위해 본문은 보지 않고 글자 수/메타데이터만 수집한다는 엔터프라이즈 제로트러스트 설계 철학을 어필합니다.
* **"5대 교과목 100% 융합"**: 리눅스/클라우드, 네트워크 패킷/DNS, 엔터프라이즈 DB, 보안관제/SIEM, 파이썬/AI가 하나의 파이프라인으로 유기적으로 엮여 있음을 입증합니다.

### 2. 발표 성공 룰
* **10초 훅(Hook)**: 시작하자마자 지루한 배경 설명 대신 "직원들이 ChatGPT에 회사 기밀을 복사해 넣는 현실"로 시작.
* **시연 이중화(2-Way)**: 발표장 네트워크 불안정을 대비해 대시보드 탭 미리 열기 + 슬라이드 5번에 핵심 3단계 고화질 캡처/GIF를 반드시 포함.

* **4계층 구조도 (SKT ALEPH 5개 과목 연계 태그)**:
  1. **수집 계층 (Endpoint Collector)** [네트워크 & 시스템]:
     * **Chrome 확장 v3.1**: Manifest V3 기반 `PASTE_ATTEMPT`(글자 수), `FILE_UPLOAD_ATTEMPT` 실시간 감시

  2. **데이터 & 감사 계층 (Enterprise DB Audit)** [데이터베이스]:

     * **영속 DB (`gigang.db`)**: `risk_history` 24시간 감사 이력 영속화 (잠복형 유출 방어)
  4. **관제 및 AI 계층 (Presentation & LLM)** [파이썬 & 생성형 AI]:
     * **16:9 Glassmorphism Bento Grid 대시보드 (`streamlit run app.py`)**: SVG 킬체인 토폴로지, 30분 TTL 링 타이머
     * **Google Gemini Flash (Google Cloud API)**: 킬체인 인과추론, MITRE ATT&CK T1567 매핑, 1-Click SOAR 대응

### 📑 Slide 6. 기술적 차별점 3선 (Technical Depth)
* **슬라이드 제목**: GIGANG만의 3대 엔지니어링 기술 혁신
* **3개 카드 레이아웃**:
  1. **🔒 제로 트러스트 프라이버시 (Zero-Content Metadata Inspection)**
     * 본문 텍스트, HTML, 파일 원본 내용은 네트워크로 **일절 전송하지 않음**
     * 글자 수(`text_length`), 파일 크기, 타임스탬프 등 정량적 메타데이터만으로 유출 판정 (노조 반발 및 사생활 이슈 원천 차단)
  2. **🛡️ 잠복형 우회 유출 방어 (Dormant Evasion Defense)**
     * "30분 기다렸다가 WATCH 풀리면 올려야지" 하는 공격자의 지연 우회 시도 차단
     * `risk_history` 소급 분석으로 과거 감시 이력 보유자의 단독 트래픽 스파이크 발생 시 즉시 `HIGH (92점)` 직행
  3. **🤖 경량·고속 Google Gemini Flash 기반 실시간 거버넌스**
     * 단순 챗봇이 아닌, 실시간 텔레메트리(접속 임직원 수, 트래픽 량)를 결합한 사이트 재학습 위험 진단
     * SQLite `domain_cache` 영구 캐싱으로 API 호출 비용 최소화 및 키 부재 시 로컬 룰베이스 Graceful Fallback 보장

### Q1. "기존 DLP나 방화벽/프록시 장비가 이미 있는데, 왜 이 시스템이 필요한가요?"
* **모범 답변**:
  > "기존 DLP와 프록시는 **'행위의 맥락(Context)'을 보지 못하기 때문**입니다.  
  > 직원이 ChatGPT에 영문 이메일이나 코딩 질문을 올리는 것은 정상 업무인데, 기존 DLP는 이를 무차별 차단하여 업무를 방해하거나, 반대로 텍스트 형태의 프롬프트 유출은 허용해 버립니다.  
  > GIGANG은 **'선행 DB 감사 로그'와 '후행 웹 트래픽'을 교차 상관분석**함으로써, **'방금 사내 기밀을 대량 조회한 사람의 복붙/전송'만을 정밀하게 타깃팅**하여 감시하므로 오탐률을 획기적으로 낮춥니다."

---

### Q2. "Chrome 확장에서 직원의 복붙 이벤트를 감시하면 사생활 침해나 노조 반발이 있지 않나요?"
* **모범 답변**:
  > "저희가 아키텍처 설계 시 가장 최우선으로 둔 원칙이 바로 **'Zero-Content(본문 미수집)'**입니다.  
  > GIGANG 확장 프로그램은 직원이 무엇을 썼는지 텍스트 본문이나 클립보드 내용을 절대 읽거나 전송하지 않습니다.  
  > 오직 **'몇 글자를 붙여넣었는가(text_length)'**, **'몇 메가바이트의 파일인가'**, **'어느 도메인인가'**라는 **숫자 메타데이터만 전송**합니다. 따라서 임직원의 사생활을 100% 보호하면서도 대량 데이터 유출 징후를 완벽히 탐지할 수 있습니다."

---

### Q3. "공격자가 영악해서, WATCH 상태가 풀리는 30분을 딱 기다렸다가 유출하면 어떻게 되나요?"
* **모범 답변**:
  > "바로 그 회피 기법을 방어하기 위해 구현된 것이 **'잠복형 유출(Dormant Exfiltration) 방어 알고리즘'**입니다.  
  > 30분 TTL이 지나 현재 상태가 NORMAL로 복귀했더라도, 영속 DB의 `risk_history` 테이블에는 이 사용자가 과거에 WATCH 대상이었다는 감사 이력이 24시간 동안 보존됩니다.  
  > 따라서 30분이 지난 후 대용량 전송이나 파일 첨부가 발생하면, 엔진이 즉시 과거 이력을 소급 대조하여 '지연 잠복형 유출 시도'로 판정하고 곧바로 **HIGH(92점)** 인시던트를 발령합니다."

---

### Q4. "Gemini LLM을 보안 판단에 쓰면 환각(Hallucination)이나 API 비용 문제가 있지 않나요?"
* **모범 답변**:
  > "두 가지 안전장치를 적용했습니다.  
  > 첫째, **판정의 분리**입니다. 침해사고 판정(FSM)은 100% 엄격한 룰 기반 상관분석 엔진이 수행하며, LLM은 침해 판정이 아니라 **'외부 사이트의 보안성 평가 및 관제 브리핑'**에만 보조적으로 활용됩니다.  
  > 둘째, **캐싱 및 폴백**입니다. 한 번 평가된 도메인은 SQLite `domain_cache`에 영구 캐싱하여 API 호출 비용을 최소화하고, 빠른 추론 속도의 **Google Gemini Flash** 모델을 사용합니다. API 키가 없거나 네트워크 오류 시에도 내장된 휴리스틱 룰베이스로 100% 안전하게 동작(Graceful Fallback)하도록 설계했습니다."
