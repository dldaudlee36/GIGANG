# 에이전트 기기 ID 변경 및 Windows 확인

## 변경

MachineGuid/호스트명 대신 최초 실행 시 UUID를 생성하여 로컬 파일에 저장합니다. 서버에 보내는 ID는 이 UUID의 SHA-256 값(기존 API와 같은 소문자 16진수 64자리)입니다. PC 이름/IP/프로그램 폴더가 바뀌어도 동일한 상태 파일을 쓰면 ID가 유지됩니다.

Windows 기본 파일: `%PROGRAMDATA%\GIGANG\device_uuid` (보통 `C:\ProgramData\GIGANG\device_uuid`). 기존 USER_START.bat의 관리자 실행 흐름을 사용합니다. 앱 업데이트 폴더와 분리되어 있습니다. macOS는 `~/Library/Application Support/GIGANG/device_uuid`, 기타 환경은 XDG 상태 폴더를 사용합니다.

파일을 읽거나 저장할 수 없으면 에이전트가 명확한 오류로 중단됩니다. 손상된 파일을 자동 덮어쓰거나 예전 중복 ID로 돌아가지 않습니다. 동일 PC의 동시 최초 실행은 완성된 UUID 하나를 사용합니다.

## 각 Windows PC에서 확인

1. 기존 에이전트를 종료하고 이 브랜치의 `guard/agent/site_access.py`를 반영합니다. `tools/check_device_identity.py`도 함께 받습니다.
2. 프로젝트 루트에서 기존 에이전트와 같은 관리자 계정/환경으로 `python tools/check_device_identity.py`를 실행합니다. 최초 실행이면 이 단계에서 ID 파일이 생성됩니다.
3. 각 PC의 `Device ID`를 비교합니다. 같은 이름의 PC A/B/C라도 값은 서로 달라야 합니다.
4. 같은 PC에서 명령을 다시 실행합니다. ID가 바뀌면 안 됩니다.
5. `USER_START.bat`으로 에이전트를 시작하고 `http://127.0.0.1:8765/health`의 `device_id`가 앞서 확인한 값과 일치하는지 봅니다.
6. Chrome 테스트 페이지를 새로고침하고 이벤트를 발생시킵니다. 대시보드에서 새 로그의 PC/IP/기기 ID가 올바른지 확인합니다.

설치 이후의 `device_uuid`를 다른 PC로 복사하거나 이 파일을 포함한 Windows 이미지를 복제하지 마세요. 파일까지 복제하면 다시 ID가 같아집니다. 배포 패키지에는 이 파일을 넣지 않습니다. 이미 복제한 경우 모든 관련 에이전트를 종료하고 각 PC의 식별 파일 관리 방안을 정한 후 재발급하세요. 재발급 시 기존 임시 허용은 연결되지 않습니다.

## 한 PC만 일시 허용하는 실제 확인

운영 업무에 영향을 주지 않는 테스트 도메인과 PC A/B로 수행합니다.

1. A/B가 서로 다른 새 ID를 보내는지 확인합니다. 기존 구버전 에이전트는 동시에 실행하지 않습니다.
2. 같은 테스트 도메인을 A/B에서 차단 상태로 확인합니다.
3. 대시보드에서 새 ID의 A만 15분 일시 허용합니다.
4. 정책 동기화 뒤 A에서는 접속되고 B는 계속 차단되는지 확인합니다. B의 에이전트는 B의 ID로 권한을 조회해야 합니다.
5. A의 일시 허용을 해제하고 두 PC 모두 다시 차단되는지 확인합니다.

이 Windows/실제 브라우저 시험은 Mac 자동 테스트로 대체할 수 없습니다. 아직 미실행입니다.

## 기존 권한과 이력

서버와 DB 스키마 변경, SQL 이전은 없습니다. 기존 `site_grants`, `site_grant_audit`, `site_blocks`는 그대로 둡니다. 새 ID에는 기존 임시 허용을 자동 연결하지 않습니다. 관리자가 필요한 허용만 새 로그의 새 ID로 다시 지정합니다. 중복된 옛 ID에서 어느 PC의 권한인지 확실히 판별할 수 없으므로 일괄 이전하지 않습니다. 예전 감사 이력은 기존 ID로 남습니다.

각 PC에 새 에이전트를 배포하기 전까지 기존 ID 중복 문제는 해소되지 않습니다. 대시보드 측 중복 ID 허용 방지 임시 조치는 실제 PC별 시험이 끝날 때까지 유지합니다.

## 자동 검증

`python -m unittest discover -s tests -p test_agent_device_identity.py`

별도 PC 저장 경로에서 UUID 분리, 재실행/이름 변경 시 유지, 동시 최초 실행, 파일 손상·저장 권한 실패 시 중단, Windows 기본 경로, 모의 권한 서버를 통한 A/B 허용 분리를 확인합니다. 실제 Windows API/파일시스템/배포와 실제 차단 동작을 검증한 것은 아닙니다.
