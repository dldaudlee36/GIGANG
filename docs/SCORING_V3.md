# GIGANG 회사 자료 사건 점수 개선 v3

통합 기준: dldaudlee36/GIGANG, 091f03e8f17fd4fdcdfc258d77a1d5a4c082a181 (2026-10-30).
팀원의 최신 실데이터 terminal_bridge와 Gemini 개선을 유지한 검토 브랜치용 소스입니다. 운영 서버 배포와 main 병합은 포함하지 않습니다.

## 1. 무엇이 달라졌나요?

목적은 회사 사이트 자료의 복사·다운로드·캡처와 외부 입력 사건에 각각 근거 있는 점수를 저장하고 정렬하는 것입니다.
에이전트는 제거하지 않았습니다. 확장과 에이전트의 로컬 검사·OCR·중앙 로그 전달을 사용합니다.

- 회사 사이트 COPY_ATTEMPT/DOWNLOAD_STARTED/DB_IMAGE_CAPTURE의 WATCH70 고정을 제거했습니다.
- 기존 학습지의 기본점·민감도·건수 배점을 회사 사이트 경로에도 적용합니다.
- 입력·첨부의 고정93/95/96 대신 자료 연관성과 민감정보를 합산합니다.
- 회사 자료 지문이 일치하면 원본 검사 건수를 외부 입력 이벤트로 전달합니다.
- 사건마다 점수·등급·근거를 사고 저장소에 남깁니다. 정상 기록은 LOW/RESOLVED, WATCH는 MEDIUM, HIGH는 HIGH로 저장합니다.
- 같은 등급의 약한 새 사건이 사용자 요약의 기존 높은 점수를 덮어쓰지 않습니다. 개별 사건은 자기 점수를 유지합니다.
- 재수신/재시작 후 저장된 동일 event_id를 다시 가산하지 않습니다.

## 2. 회사 사이트에서 가져올 때

회사 사이트는 https://desktop-oli.tail2bbbea.ts.net 의 /db 고객표와 /db/download입니다.

기본점(부서 규칙): 비허용60 / 평소 초과55 / 부서 미등록55 / 캡처60 / 검사 불가62 / 패턴0건50 / 평소 이하25.
민감도: 주민번호·카드12 / 계좌9 / 전화·이메일4. 가장 높은 한 종류만 반영합니다.
건수: 3건5 / 10건10 / 30건14. 가장 많은 종류의 건수를 사용합니다.
파일 다운로드는 +5. RECORD 최대59 / WATCH60~89.

최근60분의 같은 데이터 건수는 누적해서 부서 기준과 건수 가중치를 판단합니다.
회사 사이트 전용 경로는 AI 접속 없이도 평가합니다. AI에 접속했다고 가정해 +6을 임의로 붙이지 않습니다.
기존 일반 Agent 정책의 AI 전후5분 +6은 보존했지만 기본 portal_only=true에서는 일반Agent 중복 로그를 재채점하지 않습니다.

부서 사용자가 실제로 매핑되어 있어야 부서 예외가 적용됩니다. 기본 users={}이면 기존 COM-2(부서 미등록) 정책을 사용합니다.

| CS로 설정한 사용자의 사건 | 계산 | 결과 |
|---|---|---|
| 이메일1건 복사 | 25+4 | 29점 기록만 |
| 주민번호3건 복사 | 60+12+5 | WATCH77 |
| 주민번호3건 파일 다운로드 | 60+12+5+5 | WATCH82 |
| 주민번호30건 복사 | 60+12+14 | WATCH86 |
| 캡처 OCR 주민번호1건·전화1건 | 60+12 | WATCH72 |
| 검사 결과 없는 복사/캡처 | 검사불가62 | WATCH62, 확인 필요 |
| 검사 불가 다운로드 | 62+5 | WATCH67, 확인 필요 |

캡처 OCR이 성공하고 DB 내용 일치가 확인되어야 캡처 사건이 생성됩니다. OCR 실패를 모든 회사 스크린샷의 탐지 성공으로 설명하면 안 됩니다.

## 3. 외부에 붙여넣기·업로드할 때

복사 점수와 반출 점수를 더하는 것이 아닙니다. 같은 자료의 민감정보 검사 결과를 활용해 이번 반출 사건을 새로 계산합니다.

반출 점수 = 기본25 + 목적지10 + 자료연관성 + 민감도 + 건수 + 현재WATCH5 + 해당되는 시간/다운로드 가산.

자료연관성은 하나만 사용합니다: 내용 일치30 / 이름·크기10 / 글자 수 유사3 / 없음0.
지문이 같은 다운로드 파일은 다운로드5를 반영합니다. OCR 이미지/텍스트를 파일 다운로드로 오인해 가산하지 않습니다.
글자 수 유사성 연결이5분 이내일 때 +6을 사용할 수 있습니다. 내용 일치에 임의의 AI 접속 시간 보너스는 붙이지 않습니다.
최종 범위0~100. 이전 v2의 목적지15/내용35/기준75에서 목적지10/내용30/기준65로 조정하여 높은 사건이 쉽게100에 포화되는 것을 줄였습니다.

- HIGH: 내용 일치 +65점 이상.
- WATCH: 40점 이상 + 자료 연결/현재WATCH/민감정보 중 하나 이상.
- 그 외 RECORD. 승인 목적지는 이번 계산에서 RECORD0으로 처리합니다.
- CRITICAL 자동 승격은 추가하지 않았습니다. 등급이 대응 수준, 점수가 같은 등급 안의 우선순위입니다.

| 현재 WATCH이고 미승인 외부 AI에 입력하는 사건 | 이번 사건 점수 |
|---|---|
| 회사자료 연결 근거 없음 | WATCH40 (기존 사용자77점은 낮추지 않음) |
| 파일명·크기만 같음 | WATCH55 |
| 내용 일치, 민감정보 건수 미확인 | HIGH70 |
| 텍스트 내용 일치 +주민번호3건 | HIGH87 |
| 다운로드 파일 내용 일치 +주민번호3건 | HIGH92 |
| 텍스트 내용 일치 +주민번호10건 | HIGH92 |
| 텍스트 내용 일치 +주민번호30건 | HIGH96 |

이 숫자는 배점 초안이며 유출 확률이 아닙니다. 이름·크기만 일치하는 사건을 어떤 조건에서 HIGH로 볼지는 팀 정책으로 별도 보완할 수 있습니다.

## 4. 실제 데이터 전달

- 회사표 복사: 선택 텍스트를 같은PC의 /inspect-content로 보내 기존 rules.scan_text로 검사합니다.
- 다운로드: 20MB 이하 CSV/TSV/TXT/XLSX를 로컬 임시파일로 검사하고 삭제합니다. 미지원/암호/용량초과/실패는 검사불가입니다.
- 다운로드 시작 때 채점하고 완료 때 지문/파일 정보를 등록합니다. 완료 이벤트를 중복 가산하지 않습니다.
- 이미지: 로컬 Windows OCR 결과의 건수를 캡처/이미지 입력 사건에 전달합니다.
- 회사 원본의 검사 결과는 확장 세션에서 지문과 함께 기억합니다. 일치한 입력에만 그 검사 결과를 이어줍니다.
- 중앙 서버에는 원문/파일/이미지/지문 대신 검사 건수·길이·출처 증거를 보냅니다.
- 고정70만 계산식으로 바꾼 것이 아니라, 확장→로컬수신기→중앙raw_data→수집기 메타데이터 전달도 수정했습니다.

지문 비교의 기존50MB/30분 세션 제한은 유지합니다. 수정·부분 복사·다른 기기에서의 동일 자료는 정확 일치에서 빠질 수 있습니다.
검사 결과가 없으면 “민감정보 없음”으로 단정하지 않고 사유에 표시합니다.

## 5. 실제로 발견해 함께 고친 연결 오류

- 확장은 /copy-event로 보내지만 Python 수신기에 해당 경로가 없던 문제.
- 확장의 새 다운로드 이벤트 형식과 Python의 로컬파일 경로 기반 형식 불일치.
- OCR 캡처 시작 함수에 인자를 하나만 전달하던 문제(실제 함수는3개 필요).
- image_ocr.py가 호출하는 image_ocr.ps1 누락. Windows 로컬 OCR 스크립트를 추가했습니다.
- .gitignore의 *.ps1 때문에 실행파일이 다시 빠지지 않도록 해당 OCR 파일만 예외 처리했습니다.
- 최신 저장소에서 삭제된 source/agent, 루트 browser_extension를 가리키던 관련 테스트 경로.

## 6. 사건 점수와 사용자 요약

예: 복사 사건77점 → 무관한 붙여넣기 사건40점.
두 사건은 각각77/40으로 저장합니다. 사용자 카드는 현재 유효한WATCH77을 유지합니다.
HIGH보다 약한 사건이HIGH 사용자를WATCH로 낮추지 않습니다.
같은 등급의 더 높은 점수는 요약을 갱신합니다. 만료된 이전 점수는 새 평가에 적용하지 않습니다.
사용자 요약은 기존 단일상태+TTL 구조이며, 모든 활성 사건의 전체 재집계/감쇠 모델까지 새로 만든 것은 아닙니다.
